# Полный сценарий: один работник от создания до актов

Версия сценария: 08.08.2026

## 1. Цель сценария

По этому сценарию можно последовательно проверить работу программы на одном
отдельном сотруднике:

**справочники → работник → комплект → поступление вещи → склад → выдача →
карточка работника → отчёты → печатные формы**.

В конце должны формироваться:

- ФПУ-26;
- приложение 1.5;
- приложение 1.7;
- личная карточка работника;
- УПД.

Сценарий рассчитан примерно на 20–30 минут.

## 2. Важное предупреждение

В этом сценарии документы намеренно проводятся. Проведение необратимо и меняет
остатки базы данных.

Чтобы не смешать проверочные данные с рабочими:

- используйте названия с префиксом **«СЦЕНАРИЙ»**;
- создайте отдельные ДПО, организацию, склад и работника;
- не используйте реального работника;
- не создавайте повторно документы, если кнопка уже была нажата;
- после проверки архивируйте тестовые справочники, но не пытайтесь удалять
  проведённые документы напрямую из базы.

## 5. Шаг 1. Войти в программу

- [ ] Открыть в браузере адрес программы в локальной сети.
- [ ] Ввести логин и пароль.
- [ ] Нажать **«Войти»**.
- [ ] Убедиться, что слева видны разделы справочников, работников, закупок,
      выдачи, отчётности и печатных форм.

Если раздел отсутствует, у пользователя нет нужного права. Для полного
сценария удобнее использовать администратора.

| Краткое наименование | СЦЕНАРИЙ — Учебное ДПО |
| Полное наименование | Учебное структурное подразделение для проверки программы |
| Код | SCN-DPO |
| Адрес | г. Калининград, учебный адрес |
| ОКПО | 00000000 |
| БЕ | SCN-BE |
| Ответственное лицо | Петров Пётр Петрович |
| Основание полномочий | Доверенность № SCN-1 |
| Номер договора | SCN-ДОГ-1 |
| Дата договора | дата сценария либо более ранняя дата |
| Номер доп. соглашения | SCN-ДС-1 |
| Дата доп. соглашения | дата сценария либо более ранняя дата |

- [ ] Нажать кнопку создания записи.
- [ ] Заполнить обязательные и перечисленные выше реквизиты.
- [ ] Сохранить.
- [ ] Найти созданное ДПО в таблице.

**Ожидаемый результат:** ДПО доступно в карточке работника и в фильтре печатных
форм. Его реквизиты будут выведены в актах.

Откройте **«Справочники → Организации»**.

- [ ] Создать организацию **«СЦЕНАРИЙ — Учебная организация»**.

### 7.2. Подразделение

Откройте **«Справочники → Подразделения»**.

- [ ] Создать подразделение **«СЦЕНАРИЙ — Учебный участок»**.
- [ ] Привязать его к учебной организации.

### 7.3. Должность

Откройте **«Справочники → Должности»**.

- [ ] Создать должность **«СЦЕНАРИЙ — Электромонтёр»**.

### 7.4. Склад

Откройте **«Справочники → Склады»**.

- [ ] Создать склад **«СЦЕНАРИЙ — Учебный склад»**.
- [ ] Выбрать учебную организацию.

### 7.5. Поставщик

Откройте **«Справочники → Поставщики»**.

- [ ] Создать поставщика **«СЦЕНАРИЙ — Учебный поставщик»**.

### 7.6. Размер и рост

Откройте **«Справочники → Размеры»**.

- [ ] Найти размер одежды **52**.
- [ ] Найти рост **176**.

Если их нет:

- создайте значение `52` с типом **«Одежда»**;
- создайте значение `176` с типом **«Рост»**.

Не создавайте одинаковое значение повторно, если оно уже есть.

## 8. Шаг 4. Создать модель номенклатуры

Откройте **«Номенклатура → Модели»**.

- [ ] Создать модель **«СЦЕНАРИЙ — Костюм сигнальный летний»**.
- [ ] Выбрать тип размера **«Одежда»**.
- [ ] Включить признак необходимости отдельного роста.
- [ ] Сохранить модель.

**Ожидаемый результат:** при поступлении и ручном добавлении в выдачу программа
требует два значения — размер одежды и рост.

### 13.2. Подобрать комплект

- [ ] Нажать **«Летний комплект»**.
- [ ] Убедиться, что в предпросмотре одна строка учебной модели.

- [ ] Проверить, что доступно на складе `1`.

Дополнительная проверка:

- [ ] Нажать **«Зимний комплект»**.
- [ ] Убедиться, что летний костюм не предлагается.

к Иванову И. И. Свободный остаток учебного склада становится равен нулю.

## 17. Что должно попасть в каждую форму

| Форма | Основные данные сценария |
|---|---|
| ФПУ-26 | ДПО, период, модель, количество, цена, НДС, итог |
| Приложение 1.5 | ДПО, должность, обеспечение и дни |

## 18. Контроль прохождения основного сценария

Основной сценарий считается пройденным, если выполнены все пункты:

- [ ] Работник создан и связан с организацией, подразделением, должностью и ДПО.
- [ ] В карточке заполнены мужской пол, размер `52` и рост `176`.
- [ ] Для должности создан мужской летний комплект.
- [ ] Поступление проведено и создало один экземпляр.
- [ ] После поступления остаток равен `1`.
- [ ] Летний комплект подобрал модель автоматически.
- [ ] Зимний комплект не предложил летнюю модель.
- [ ] Выдача проведена без дублей.
- [ ] Экземпляр получил статус **«Выдан»** и привязан к работнику.
- [ ] Остаток склада стал равен `0`.
- [ ] В карточке работника появилась стоимость и история выдачи.
- [ ] В движениях есть поступление и выдача.
- [ ] Сформированы и открываются все пять печатных форм.
- [ ] В приложении 1.7 и личной карточке найден учебный работник.

## 19. Дополнительное продолжение: возврат работника

- [ ] Создать документ на Иванова И. И.

- [ ] Добавить выданный экземпляр по записанному инвентарному номеру.
- [ ] Состояние: **«Хорошее»**.
- [ ] Куда направить: **«На склад»**.
- [ ] Провести возврат.

После проведения проверьте:

- [ ] экземпляр больше не привязан к работнику;
- [ ] экземпляр снова находится на учебном складе;
- [ ] свободный остаток снова равен `1`;
