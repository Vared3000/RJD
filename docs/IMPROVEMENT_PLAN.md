# План доработки ERP «Учёт спецодежды»

Дата создания: 2026-08-08
Назначение: единый рабочий план для продолжения разработки в разных сессиях и разными моделями.
Целевая эксплуатация: сервер внутри одной локальной сети предприятия, без публичного интернет-доступа.

## Как пользоваться планом

- Перед началом любой задачи прочитать `CLAUDE.md`, `HANDOFF.md` и
  `docs/architecture.md`.
- Проверить `git status` и не перезаписывать чужие незакоммиченные изменения.
- Выполнять только одну задачу плана за раз.
- Не смешивать независимые задачи в одном коммите.
- Перед миграциями проверить состояние dev-БД и сделать резервную копию, если
  изменение затрагивает существующие данные.
- Уже применённые или опубликованные миграции не редактировать. Создавать
  следующую миграцию, кроме ещё не опубликованной активной миграции текущей
  задачи.
- Бизнес-операцию, изменение экземпляра, движения и запись истории выполнять
  в одной транзакции.
- После завершения задачи обновить этот файл, `README.md` и `HANDOFF.md`.

Обязательные проверки после каждой задачи:

```powershell
pnpm.cmd lint
pnpm.cmd format:check
pnpm.cmd --filter @workwear/server test
pnpm.cmd --filter @workwear/client build
```

Если тестовая инфраструктура ещё не изолирована от dev-БД, перед запуском
backend-тестов проверить правила очистки из `docs/architecture.md`.

# Этап A. Стабилизация текущей разработки

## Задача 1. Завершить комплекты по полу и сезону

Статус: **Готово** (2026-08-08).

### Цель

Комплект должности должен корректно учитывать пол работника, сезон,
унисекс-позиции, старые позиции без сезона и работников с незаполненным полом.

### Исходное состояние

В рабочем дереве уже находятся незакоммиченные изменения:

- `client/src/pages/employees/KitsPage.jsx`;
- `server/src/database/models/position-kit-item.model.js`;
- `server/src/modules/issuance/documents/issuance.service.js`;
- `server/src/modules/kits/kit-item.validation.js`;
- новая миграция `0054-add-kit-item-gender.js`.

Старый уникальный индекс разрешает только одну строку на
`position_id + model_id`, поэтому не позволяет завести отдельные сезонные или
гендерные варианты одной модели.

### Необходимые изменения

- [x] Добавить `gender` в `position_kit_items`.
- [x] Ограничить значения `male`, `female`, `NULL`.
- [x] Заменить уникальность `position_id + model_id` на комбинацию,
      учитывающую `season` и `gender`.
- [x] Корректно обработать `NULL` через `NULLS NOT DISTINCT` либо выражения
      `COALESCE`.
- [x] Определить детерминированный приоритет позиции:
  1. точное совпадение пола и сезона;
  2. унисекс нужного сезона;
  3. архивная позиция без сезона;
  4. исключение повторной модели из-за пересечения wildcard-позиций.
- [x] Синхронизировать `applyKit` и `previewKit`.
- [x] Обновить Swagger/OpenAPI и подсказки UI.
- [x] Не допускать дублирования одной модели/размера/роста в документе выдачи.

### Тесты

- [x] Мужчина получает мужские и унисекс-позиции.
- [x] Женщина получает женские и унисекс-позиции.
- [x] Работник без пола не блокируется.
- [x] Летняя позиция не попадает в зимний комплект.
- [x] Одинаковая модель не появляется дважды.
- [x] Разрешены отдельные комбинации `summer/male`, `summer/female`,
      `winter/male`, `winter/female`.
- [x] Старые строки с `season=NULL` продолжают работать предсказуемо.

### Критерий готовности

Автоподбор и предпросмотр возвращают одинаковый, недублирующийся комплект.

### Результат первого релиза

- Добавлены миграции `0054-add-kit-item-gender.js` и
  `0055-fix-kit-item-variant-uniqueness.js`; 150 существующих строк сохранены.
- Точный сезон имеет приоритет над старой строкой без сезона; для указанного пола
  точный вариант имеет приоритет над унисексом. Для работника без пола сначала
  выбирается унисекс, затем один стабильный подходящий вариант.
- Предпросмотр и автозаполнение используют один алгоритм и возвращают не более
  одной строки каждой модели.
- Пройдены 18 интеграционных тестов, ESLint, production build и проверка миграций
  на чистой временной схеме PostgreSQL.
- Общий `format:check` пока отмечает 13 ранее изменённых файлов других модулей;
  это вынесено в задачу 2 и не смешивается с первым релизом.
