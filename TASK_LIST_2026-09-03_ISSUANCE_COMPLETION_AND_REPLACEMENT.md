# ТЗ: сборка, доукомплектовка и плановое переодевание работников

Дата фиксации: 03.09.2026

Статус: **реализовано и проверено 03.09.2026**.

## 1. Разделение позиций при выдаче

После добавления вещей в черновик выдачи система должна проверять фактический
остаток выбранного склада отдельно по каждой комбинации:

- модель;
- размер;
- рост, если он требуется для модели.

В таблице выдачи для каждой позиции необходимо показывать:

- «Требуется» — полное количество, добавленное в документ;
- «Есть на складе» — доступный остаток;
- «В сборку» — количество, которое можно выдать сейчас;
- «Не хватает» — количество для доукомплектовки.

Формула разделения:

```text
В сборку = min(Требуется, Доступно на складе)
Не хватает = Требуется - В сборку
```

Пример: работнику требуется два плаща, на складе есть один. Один плащ попадает
в задание на сборку, второй — в задачу на доукомплектовку.

## 2. Проведение первоначальной выдачи

- В задание на сборку попадают только позиции и количества из колонки
  «В сборку».
- При проведении выдаются только фактически доступные и собранные экземпляры.
- В первоначальную сохранную расписку попадают только фактически выданные вещи.
- Для количества «Не хватает» при проведении создаётся задача на
  доукомплектовку.
- Редактирование черновика само по себе не должно создавать задачи, иначе после
  изменения или удаления строк останутся ошибочные задания.
- Если по одной строке требовалось два экземпляра, а выдан один, задача должна
  хранить точный остаток: один экземпляр.

## 3. Выполнение задачи на доукомплектовку

- После появления подходящей вещи задача переходит в состояние
  «Можно собрать».
- Из задачи создаётся отдельный документ довыдачи на того же работника.
- Для довыдачи формируется отдельное задание на сборку.
- После проведения довыдачи формируется отдельная сохранная расписка.
- Задача закрывается только по фактически проведённому количеству.
- Частичная довыдача уменьшает остаток задачи, но не закрывает её полностью.

## 4. Задачи на плановое переодевание

У выданной одежды есть срок износа. Например, плащ используется четыре года.
При проведении выдачи необходимо зафиксировать:

- дату фактической выдачи;
- срок износа на момент выдачи;
- рассчитанную дату плановой замены.

Изменение срока в справочнике или комплекте в будущем не должно менять уже
зафиксированную дату замены ранее выданной вещи.

За один календарный месяц до плановой даты замены система автоматически создаёт
уведомление и задачу типа «Переодевание».

Пример:

```text
Дата выдачи: 15.09.2026
Срок износа: 4 года
Плановая замена: 15.09.2030
Уведомление и задача: 15.08.2030
```

## 5. Содержание задачи на переодевание

Задача должна содержать:

- работника, его должность и ДПО;
- модель одежды;
- размер и рост;
- необходимое количество;
- дату первоначальной выдачи;
- зафиксированный срок износа;
- плановую дату замены;
- оставшееся количество дней;
- наличие подходящих экземпляров на складе.

Для задачи на переодевание применяется та же логика разделения:

- доступное количество попадает в задание на сборку;
- недостающее количество ожидает поступления;
- после появления товара создаётся отдельная выдача типа «Переодевание»;
- новая выдача получает собственное задание на сборку и сохранную расписку;
- старая вещь оформляется отдельным возвратом с дальнейшим маршрутом.

## 6. Статусы задач

Для доукомплектовки и переодевания использовать понятные пользовательские
статусы:

- «Запланировано» — срок замены ещё не наступил;
- «Можно собрать» — необходимый остаток появился на складе;
- «Ожидает поступления» — нужных вещей недостаточно;
- «Создана выдача» — сформирован отдельный черновик довыдачи/переодевания;
- «Выполнено» — необходимое количество фактически выдано;
- «Просрочено» — плановая дата прошла, задача не выполнена;
- «Отменено» — задача больше не актуальна.

## 7. Автоматическая проверка

Так как программа работает в локальной сети и сервер может быть выключен,
проверку сроков необходимо выполнять:

1. при запуске сервера;
2. затем один раз в сутки;
3. дополнительно при открытии страницы задач — как защиту от пропущенного
   ежедневного запуска.

Повторная проверка не должна создавать дубли задач.

Уведомления показывать:

- счётчиком возле пункта меню «Задачи»;
- на главной странице;
- внутри списка задач с сортировкой по ближайшей/просроченной дате.

## 8. Обязательные ограничения

- Не создавать повторную задачу для одной и той же выдачи и позиции.
- Не создавать задачу для уже возвращённой или списанной вещи.
- Отменять ещё не выполненную задачу, если вещь возвращена досрочно.
- Не создавать новые задачи для уволенных и архивных работников.
- Несколько вещей одного работника с близкими датами разрешается объединять в
  одну задачу с несколькими строками, но каждая строка сохраняет собственный
  срок и остаток.
- При параллельной работе пользователей нельзя обещать один физический
  экземпляр двум выдачам. Перед печатью окончательного задания на сборку нужен
  повторный контроль остатка либо резервирование экземпляров.

## 9. Критерии приёмки

1. При потребности 2 и остатке 1 система показывает «В сборку: 1» и
   «Не хватает: 1».
2. В задание на сборку попадает 1 вещь, а задача доукомплектовки создаётся на 1.
3. В первоначальной выдаче и расписке отсутствует ещё не выданная вещь.
4. Частичная довыдача корректно уменьшает остаток задачи.
5. За календарный месяц до окончания срока износа появляется ровно одна задача
   на переодевание.
6. Досрочный возврат отменяет будущую задачу замены.
7. Из выполненной задачи создаётся отдельная выдача и отдельная сохранная
   расписка.
8. Перезапуск сервера и повторное открытие страницы не создают дубликаты задач.

## 10. Что реализовано

- В черновике выдачи показаны колонки «Требуется», «Есть на складе»,
  «В сборку» и «Не хватает».
- PDF/Excel-задание на сборку получает только фактически доступное количество.
- Из задачи доукомплектовки создаётся отдельная выдача только на доступный
  остаток; частичное выполнение сохраняет точный остаток задачи.
- Для каждой фактически выданной вещи сохраняются снимок срока износа и дата
  плановой замены. На один экземпляр создаётся не более одной задачи.
- Старые выданные вещи однократно добавляются в календарь миграцией 0082 по
  действующему нормативу комплекта (для старой истории снимка раньше не было).
- За месяц до даты замены задача появляется в интерфейсе, счётчике меню и на
  главной странице. Проверка выполняется при старте сервера, ежедневно и при
  открытии списка задач.
- Досрочный возврат отменяет будущую задачу; отмена проведения возврата
  восстанавливает её. Уволенные и архивные работники исключаются автоматически.
- Страница переименована в «Задачи на выдачу и переодевание» и показывает тип,
  должность, ДПО, склад, наличие, исходную выдачу, инвентарный номер, срок и
  плановую дату.
- Добавлены миграции 0081–0082, календарные unit-тесты и интеграционные проверки
  выдачи/доукомплектовки/возврата.
