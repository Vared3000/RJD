
# PROJECT_SPECIFICATION.md

# Техническое задание
## ERP-система учета аренды спецодежды

Версия: 1.0

## 1. Цель проекта
Разработать корпоративную ERP-систему для учета спецодежды, работающую в локальной сети предприятия.
Система сопровождает полный жизненный цикл каждой единицы одежды:
Закупка → Оприходование → Склад → Выдача → Эксплуатация → Возврат → Стирка → Ремонт → Повторная выдача → Списание.

## 2. Технологический стек
- Frontend: React (Feature-Sliced Design)
- Backend: Node.js + Express
- ORM: Sequelize
- PostgreSQL
- REST API
- JWT
- Docker Compose
- Swagger/OpenAPI

## 3. Архитектурные принципы
- REST
- SOLID
- DRY
- KISS
- Компонентная разработка
- Разделение Controller / Service / Repository
- Никакой бизнес-логики во Frontend.

## 4. Развертывание
Система разворачивается исключительно на локальном сервере организации.
Работа без доступа к Интернету.
Поддержка резервного копирования БД.

## 6. Закупки и оприходование
Документ "Поступление":
- поставщик
- договор
- номер накладной
- дата
- ответственный
- склад
- позиции
- размеры
- количество
- закупочная цена
- стоимость для работника
- НДС
- партия

После проведения:
- создаются экземпляры одежды (или увеличиваются остатки);
- формируется движение склада;
- обновляются остатки.

## 7. Номенклатура
Модель → Размер → Экземпляр.
Каждый экземпляр имеет:
инвентарный номер, QR/штрихкод, статус, состояние, стоимость, партию, историю.

## 8. Работники
Карточка содержит:
личные данные;
стаж (расчет автоматически);
размеры;
историю выдач;
историю документов;
стоимость имущества;
быстрый подбор комплекта.

## 9. Комплекты
Система автоматически предлагает комплект по должности и размерам работника.
Проверяет наличие на складе.
Создает документ выдачи.

## 10. ДПО
Полный CRUD:

редактирование;
архивация;
удаление;
поиск;
история изменений.

## 11. Складские документы
- поступление;
- выдача;
- возврат;
- перемещение;
- инвентаризация;
- корректировка;
- ремонт;
- стирка;
- списание.

Любое изменение остатков производится только документом.

## 12. Отчетность

- ДПО;

- склады;
- поставщики;
- остатки;
- закупки;
- списания;
- ремонты;
- стоимость имущества.

- фактические дни обеспечения;
- даты приема/увольнения;
- период выдачи одежды;
- исторические цены.

## 16. Правила разработки Claude

Роль:
Ведущий архитектор и Senior Full Stack Developer.

Claude обязан:
- самостоятельно анализировать код;
- соблюдать существующую архитектуру;
- писать чистый код;
- создавать миграции;
- создавать модели;
- создавать REST API;
- создавать React-компоненты;
- писать комментарии только там, где они действительно нужны;
- сопровождать изменения кратким отчетом.

Claude НЕ должен запрашивать подтверждение для:
- безопасных консольных команд;
- npm install;
- npm uninstall;
- создания файлов;
- создания папок;
- создания компонентов;
- генерации миграций;
- генерации моделей;
- генерации роутов;
- генерации сервисов;
- рефакторинга;
- удаления собственных временных файлов.

Исключение:
Перед потенциально разрушительными действиями (массовое удаление кода, изменение схемы БД без миграции, удаление данных, изменение истории Git) Claude обязан предупредить.
