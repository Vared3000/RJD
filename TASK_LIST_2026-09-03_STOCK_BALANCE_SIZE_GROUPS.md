# ТЗ: группировка размеров в фильтре складских остатков

Дата фиксации: 03.09.2026

Статус: реализовано 03.09.2026, автоматические проверки пройдены.

## Результат реализации

- Общий компонент `Select` поддерживает визуальные группы `optgroup`.
- Размеры в фильтре остатков разделены по назначению и естественно
  отсортированы внутри каждой группы.
- После выбора модели остаётся только совместимый тип размера.
- Для безразмерной модели фильтр блокируется с понятным пояснением.
- Несовместимый ранее выбранный размер сбрасывается при смене модели.
- Рост отделён от размеров и отсортирован по возрастанию.
- Добавлены два автоматических теста группировки и фильтра модели.

## 1. Проблема

На странице **«Склады → Остатки»** значения фильтра **«Размер»** сейчас идут
вперемешку. Например, рядом отображаются размеры одежды, ремня и головного
убора. Из-за одинаковых числовых значений пользователь не может быстро найти
нужный размер.

## 2. Требуемое поведение

В выпадающем списке **«Размер»** значения должны отображаться отдельными
визуальными группами по типу размера:

1. Одежда.
2. Обувь.
3. Головной убор.
4. Перчатки.
5. Ремень.
6. Прочее — только для реально существующих типов, не вошедших в основные
   группы.

Заголовок группы не является значением фильтра и не должен выбираться.

Внутри каждой группы использовать естественную сортировку:

- числовые значения — по возрастанию (`36`, `38`, `40`, `42`);
- текстовые значения — от А до Я без учёта регистра;
- при равных отображаемых значениях использовать стабильный дополнительный
  порядок, чтобы пункты не менялись местами после обновления страницы.

Нельзя снова объединять одинаковые числа разных типов в один общий список:
например, `Головной убор: 54` и `Ремень: 54` должны находиться в своих группах.

## 3. Зависимость от выбранной модели

- Если модель не выбрана, показывать все доступные размеры, сгруппированные по
  типам.
- Если выбрана модель, показывать только размеры того типа, который указан в
  карточке этой модели. Например, для рубашки показывать только группу
  **«Одежда»**, а размеры ремней и головных уборов скрывать.
- Если у модели размер не требуется, фильтр размера сделать недоступным и
  показать понятную подсказку **«Для выбранной модели размер не используется»**.
- При смене модели сбрасывать ранее выбранный размер, если он несовместим с
  новой моделью.
- Фильтр **«Рост»** остаётся отдельным. В нём должны отображаться только значения
  типа «Рост», также по естественному возрастанию.

## 4. Требования к реализации

- Группировка должна применяться ко всему набору доступных размеров, а не только
  к текущей странице справочника.
- Фактическая фильтрация остатков продолжает выполняться по идентификатору
  размера; изменение относится к представлению и не требует миграции данных.
- Существующие параметры URL и кнопка **«Сбросить фильтры»** должны продолжать
  работать.
- После обновления страницы выбранный допустимый размер должен восстановиться.
- Не менять справочник размеров и не создавать дубликаты записей ради
  группировки.

## 5. Критерии приёмки

1. Без выбранной модели размеры в списке разделены заголовками типов и не идут
   вперемешку.
2. В каждой группе числовые размеры расположены по возрастанию, текстовые — от
   А до Я.
3. При выборе модели «Рубашка» в фильтре остаются только размеры одежды.
4. Значения `54` для головного убора и ремня находятся в разных группах.
5. При смене модели несовместимый выбранный размер автоматически сбрасывается.
6. Выбор размера корректно фильтрует таблицу и выгрузки Excel/PDF так же, как до
   изменения интерфейса.
7. Кнопка **«Сбросить фильтры»** возвращает полный сгруппированный список.

## 6. Проверки

- Добавить клиентский тест построения групп и естественной сортировки.
- Проверить сценарии: модель не выбрана; выбрана одежда; выбрана обувь; модель
  без размера; смена модели при уже выбранном размере; восстановление фильтра
  из URL.
- Вручную проверить список на данных с одинаковыми числами у разных типов
  размеров.
