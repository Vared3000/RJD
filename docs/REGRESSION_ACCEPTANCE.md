# Финальная регрессионная приёмка

Дата актуализации: 20.08.2026.

## Одна команда проверки

Из корня проекта:

```powershell
pnpm.cmd release:check
```

Команда последовательно и с остановкой при первой ошибке выполняет:

1. чистую установку всех миграций и сидов во временной схеме PostgreSQL;
2. полный набор backend-тестов в отдельной временной схеме;
3. ESLint и проверку форматирования;
4. production-сборку frontend;
5. Playwright E2E в ещё одной отдельной временной схеме.

Рабочая база данных этим прогоном не изменяется. Временная схема удаляется даже
при ошибке теста.

## Что покрывает автоматический прогон

Playwright выполняет два уровня проверки четырьмя сценариями:

- браузерный вход администратора, поиск по меню, скачивание Excel-шаблона,
  отсутствие штрихкодов в рабочем меню, доступность раздела
  `Дополнительно`, реестра партий и всех пяти типов конструктора макетов;
- сквозной бизнес-цикл через реальный HTTP API:
  работник и комплект → поступление → исправление поступления → выдача →
  исправление выдачи → возврат → стирка → ремонт → повторная выдача →
  инвентаризация → корректировка состояния → списание → отчёт → личная
  карточка Excel.

Backend-набор дополнительно проверяет права доступа, конкурентное проведение,
остальные отчёты и печатные формы, версии месячных актов, редактирование
проведённых документов, резервное копирование, Windows-сценарии и ограничения
LAN-конфигурации.

## Автоматическая проверка установленного Windows-сервера

После первичной установки и создания свежей проверенной резервной копии
запустите `Провести приёмку.bat`. Сценарий сформирует Markdown- и JSON-отчёты в
`logs/acceptance` и вернёт ненулевой код, если не прошла хотя бы одна
автоматическая проверка.

Он проверяет точные версии зависимостей, службу и автозапуск, PostgreSQL,
локальный и LAN healthcheck, firewall, отсутствие публикации портов 4000/5432,
Cloudflare Tunnel, задания Планировщика, SHA-256 основной и второй копий и
доказательство тестового восстановления. Порядок и форма подписания приведены
в [протоколе Windows-приёмки](WINDOWS_ACCEPTANCE_PROTOCOL.md).

## Проверки на целевом сервере заказчика

Эти пункты нельзя достоверно подтвердить на компьютере разработчика. Их нужно
выполнить после установки в локальной сети и приложить к акту приёмки дату,
ФИО проверяющего и результат:

- [ ] Подтверждена совместимая Windows, серверу закреплён постоянный IP или DNS-имя.
- [ ] После перезагрузки сервер и приложение запускаются без входа пользователя.
- [ ] С двух рабочих компьютеров LAN открывается приложение и выполняется вход.
- [ ] PostgreSQL и служебный backend-порт недоступны напрямую из
      пользовательской подсети; снаружи доступен только HTTP-порт приложения.
- [ ] Создана резервная копия с SHA-256 и вторая копия на другом компьютере LAN.
- [ ] Выполнено тестовое восстановление во временную базу, контрольные количества
      работников, экземпляров, документов и движений совпали.
- [ ] Приложение не имеет публичного интернет-адреса и не использует туннели.
- [ ] Зафиксировано предоставление одноразовых прав локального администратора для
      установки служб, firewall и планировщика резервных копий.

Подробные команды приведены в `docs/WINDOWS_INSTALLATION.md`,
`docs/LAN_DEPLOYMENT.md` и `docs/WINDOWS_BACKUP.md`.
