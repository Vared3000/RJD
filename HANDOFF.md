## Локальное окружение — важные отличия от "стандартного" сетапа

- **Docker не установлен** на этой машине. `docker-compose.yml` написан и
  предназначен для сервера предприятия (раздел 4 ТЗ — развёртывание без
  интернета), но локальная разработка идёт напрямую против **локального
  PostgreSQL 18** (Windows-сервис `postgresql-x64-18`, уже запущен).
- БД `workwear_erp`, роль `workwear_app` / пароль `workwear_app_password` —
  создана отдельно от суперпользователя, не пересекается с базой `cleanflow`
  соседнего (чужого) проекта на этой же машине.
- `.env` в корне уже заполнен рабочими значениями (скопирован из
  `.env.example`), включая `BOOTSTRAP_ADMIN_PASSWORD=change-me-on-first-login`
  для входа как `admin`.
- **Git Bash на Windows ломает кириллицу в inline-аргументах** к нативным
  .exe (`curl -d '{"name":"Русский текст"}'`, `psql -c "... WHERE x = 'рус'"`)
  — байты манглятся при передаче argv в дочерний процесс. Для тестовых
  запросов с кириллицей писать payload в файл и передавать через
  `curl --data-binary @file.json` / `psql -f file.sql`, либо гонять кириллицу
  только через stdin (пайпы это не ломает). Сами данные в БД/приложении не
  повреждаются — проверено сквозным byte-level тестом, проблема только в
  этом одном инструменте тестирования.

## Как проверялась каждая фича (и как проверять дальше)

1. `pnpm --filter @workwear/server test` — автотесты (сейчас 9/9, файлы в
   `server/src/tests/*.test.js`). **Ходят в реальную dev-БД**, не в откатываемой
   транзакции — каждый новый тест обязан подчищать за собой через
   `t.after()`, см. `docs/architecture.md` раздел "Тесты, создающие данные".
2. Живой прогон в headless-браузере через Playwright, вручную установленный в
   scratchpad (`C:\Users\user\AppData\Local\Temp\claude\...\scratchpad\pw-check\`,
   там же `driver.mjs` — REPL-драйвер с командами `launch/nav/fill/click-text/
   click-dialog-text/select-label/wait-text/ss/console-errors/quit`). Это НЕ
   часть репозитория проекта — придётся либо переустановить в новом
   scratchpad (`npm install playwright && npx playwright install chromium`),
   либо написать драйвер заново по образцу `.claude` skill `run` →
   `examples/playwright.md`. Оправдало себя дважды: поймало реальные баги,
   которые не всплыли бы при проверке только по коду или только через curl
   (несработавшие defaultValue в формах, `FOR UPDATE` через LEFT JOIN).
3. После ручных проверок — чистить тестовые данные из dev-БД (см. примеры
   `DELETE FROM ...` в истории команд/`docs/architecture.md`), чтобы не
   путать реальные данные с мусором на следующей сессии.
